# MODX Installer

Локальный сайт на MODX Revolution одной командой: официальный дистрибутив, Nginx, PHP-FPM и MariaDB в Docker. Браузерный установщик проходить не нужно.

Требования: PHP 8.2+ с `curl`, `dom`, `zip`, работающий Docker с Compose 2.20+, интернет. Поддерживаются macOS и Linux, ARM64 и AMD64; для Windows используйте WSL2. Запускайте сайты от обычного пользователя хоста, без root: UID/GID определяются по владельцу файлов, расширение PHP POSIX не требуется. Окружение предназначено для локальной разработки.

## Установка

Скачайте PHAR и контрольную сумму из [релиза](https://github.com/crystaldaking/modx-installer/releases/latest):

```sh
mkdir modx-cli && cd modx-cli
gh release download --repo crystaldaking/modx-installer --pattern modx.phar --pattern SHA256SUMS
shasum -a 256 -c SHA256SUMS
chmod +x modx.phar
mkdir -p "$HOME/.local/bin"
mv modx.phar "$HOME/.local/bin/modx"
# Добавьте $HOME/.local/bin в PATH, если каталог ещё не добавлен.
modx doctor
```

Либо клонируйте репозиторий, переключитесь на `v0.1.1`, выполните `composer install --no-dev` и запускайте `./bin/modx`. Отдельная регистрация в Packagist пока не выполнена.

## Использование

```sh
modx new my-site
modx new my-site --version=3.2.4-pl --port=8090 --language=ru
modx new . --no-start                 # Только в полностью пустой папке
cd my-site
modx up                              # Запуск и завершение отложенной установки
modx down                            # Остановка с сохранением базы
modx logs --follow --service=php
modx doctor --project-dir=.
```

`--modx-version=3.2.4-pl` — эквивалент `new --version=3.2.4-pl`. Без указания версии выбирается последний стабильный MODX 3 из официальных Git-тегов. GitHub ограничивает неавторизованные запросы: явная версия позволяет обойти обнаружение версии. `--no-start` скачивает MODX, но не требует работающего Docker.

Адрес сайта, админки, логин и первоначальный пароль выводятся после успешной установки. Пароли случайные, хранятся в `.env` с правами `0600` и исключены из Git. Не публикуйте `.env` и вывод с паролями. Изменение `.env` после установки не меняет пароли уже созданных учётных записей.

Каждый проект получает отдельное имя Compose и отдельную базу. По умолчанию выбирается свободный порт 8080–8180. Запускайте первый проект до создания следующего либо задавайте разные `--port`: подготовленные без запуска проекты не резервируют порты. HTTP доступен только через `127.0.0.1`, порт базы наружу не публикуется. Apple Silicon использует нативные ARM64-образы.

CLI не перезаписывает непустые каталоги, включая скрытые файлы. Выбранная версия, источник ZIP и его SHA-256 записываются в `modx.json`. Для проверки по независимо полученной доверенной сумме передайте `--sha256=...`. Образы Docker закреплены по веткам версий, без неизменяемых digest.

Установочный XML создаётся во временном каталоге контейнера вне webroot и удаляется при завершении PHP. Перед удалением `setup` CLI отдельно проверяет загрузку MODX и пароль администратора. При ошибке данные сохраняются: изучите `modx logs` и `app/core/cache/logs/`, устраните причину и повторите `modx up`. Автоматический откат частичной установки не предусмотрен; существующий конфиг защищён от повторной установки поверх базы.

`modx down` сохраняет базу в Docker volume. База не хранится в Git — резервируйте её отдельно вместе с `.env` и файлами сайта. Перенос установленного проекта, production-развёртывание, HTTPS и обновление CMS не автоматизированы в v0.1.

Полное описание структуры, восстановления, ограничений и разработки: [README.md](README.md). Лицензия инструмента — [MIT](LICENSE). Проект независимый, не является официальным продуктом MODX.

## Обновление с v0.1.0

Обновите PHAR или исходники CLI. Команда `up` использует исправленные встроенные скрипты установки и проверки даже для старых проектов, проверяет настоящую базу и HTTP-ответ менеджера. Конфигурацию Docker и существующий volume она не перезаписывает. Новые проекты получают случайный идентификатор volume, поэтому повторное создание папки не подключит старую базу.

После установки первоначальные `ADMIN_*` можно удалить из `.env`; запуск больше от них не зависит. Значения `.env` теперь буквальные и однострочные: `KEY=value` или `KEY='значение с пробелами'`. Команды, подстановка `$VAR`/`${VAR}` и склеивание кавычек не выполняются. Если использовались ссылки на переменные, заранее замените их фактическими значениями. Диагностика синтаксиса не показывает пароли.

У файлов, созданных старым PHAR, может отсутствовать право записи. В папке такого сайта выполните:

```sh
chmod u+w compose.yaml docker/php/Dockerfile docker/nginx/default.conf docker/install.php docker/verify.php
```

Добавьте `/.modx.lock` в `.gitignore` сайта. Этот файл защищает от одновременных `up`/`down`. Новые проекты также получают healthcheck для PHP и веб-сервера; старые поддерживаются за счёт отдельной проверки готовности из CLI.
